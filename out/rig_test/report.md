# PoseRig 分层立绘 puppet — 交付说明（2026-11-09）

代码：`units/rig_sprite.py`（自包含，未改动任何既有文件）
测试：`tools/rig_pose_test.py` → `out/rig_test/{rig_pose_sheet.jpg, rig_vs_sprite.jpg, timings.json}`

一句话：把 `assets/gen/char/*_cut.png` 这些生图立绘变成能**转头、抬刀、劈砍、换表情**的 puppet，
用「权重场蒙皮 + 多角度头部替换 + 整姿势键帧」而不是硬切图层；和 `units/sprite.py` 的
`SpriteLayer.draw()` 接口同构（显示空间 float32 0..1，返回 `(fr, alpha_map)`），可以挂在 `SPRITE_MODE` 下直接替换。

### 先看结论

* **能用**：`raise`（举刀）、`slash`（落刀）、`head_turn ±0.6`、`expr angry/smirk` 都已经能用；
  单帧 52~107 ms（要求 <250ms），比现有单张立绘 sprite（114ms）还快。
* **最像样的两个姿势**：① `key='raise'`（横刀举过头，逐像素干净）② `key='slash', key_w=1`（下劈落刀，
  马尾衣摆都在动）。转头里 `head_turn=-0.6` 最自然。
* **最大缺陷**：`arm_r ≥ 60°` 靠纯骨架蒙皮会在大袖/腋下拉出淤积 + 刀镡变成深色椭圆；
  抬刀请走整姿势键帧（`key='raise'`），`arm_r` 只当 0~45° 微调。键帧中间值（`key_w≈0.5`）必然双影，
  只能用快过渡 + `mblur` 掩盖（样张里那张就是这么渲的）。

样张：`out/rig_test/rig_pose_sheet.jpg`（12 格姿势 + 每格耗时）、
`out/rig_test/rig_vs_sprite.jpg`（与现有单张立绘对比）、`out/rig_test/timings.json`。

## 1. API

```python
from units.rig_sprite import PoseRig

rig = PoseRig(base='assets/gen/char', work_w=2048)   # work_w 实际封顶 1280（1024 已够，2048 只更慢）
rig.warm()                                          # 载入时调一次：预解码全部贴图（~2.4s），之后每帧无抖动

fr, a = rig.draw(fr, t, pose, dst=(960, 900), h=680,
                 look=None, rim=None, grade=None, alpha=1.0, defocus=0.0, mblur=0.0, wrap=0.0)
```

* `dst` = **脚底中点**的画面坐标；`h` = 人物总高（脚底 → 头顶发梢）像素。
  单位空间里 `y=0`=脚底、`y=1`=眼线、`y≈1.11`=头顶发梢，画面高度 = `h/1.11` 每单位。
* `grade / rim / look / alpha / defocus / mblur / wrap` 与 `units/sprite.py` 的 `SpriteLayer.draw()` 同名同义：
  `grade`、`rim` 用的是 `sprite.py` 里 `_front()` 的同一套公式，`look in {'sil','ink','paper','neg','shadow'}`
  **直接 import `units/sprite._look` + `red_mask` 复用**（没有抄第二份）。默认值与 `sprite.py` 一致。
* `t` 只用于呼吸（±0.4% 身高起伏）。

### pose 字典

| 键 | 范围 | 含义 / 约定 |
|---|---|---|
| `head_turn` | −1 … 1 | 头部偏转。**负 = 转向画面左**，正 = 画面右。0=正面，±1≈90° 侧脸 |
| `head_pitch` | −0.5 … 0.5 | 抬头/低头；正 = 抬头（绕颈 9°，二维近似） |
| `lean` | −0.3 … 0.3 | 前后倾；正面视角按「画面内脊柱倾斜 13°」近似（不是真透视缩短） |
| `twist` | −0.3 … 0.3 | 上身扭转；用绕髋水平剪切 0.16 近似（正 = 右肩向前/画面右移） |
| `arm_r` | 0 … 110 | **右臂 = 画面左臂 = 持刀手**抬起角（绕肩，正 = 抬起外张） |
| `elbow_r` | 0 … 90 | 右肘屈（正 = 小臂向体内收） |
| `arm_l` / `elbow_l` | 同 | 左臂 = 画面右臂（空手） |
| `knee` | −0.2 … 0.2 | 正 = 重心下沉：髋部整体下移 `0.10·h`，脚底不动（腿按高度渐变压缩） |
| `sword` | −170 … 170 | 刀相对手（腕）的旋转，正 = 刀尖向内上收 |
| `expr` | `'calm'\|'angry'\|'smirk'\|'look'` | `calm` 直接用 base；其余贴脸部补丁（见 §3.3） |
| `body_turn` | −1 … 1.7 | **可选**，身体朝向。默认 0（永远用正面）——理由见 §4 缺陷 2 |
| `key` | `'raise'\|'slash'\|'draw'` | 整姿势键帧 |
| `key_w` | 0 … 1 | 键帧权重（默认 1）。中间值 = 两个姿势交叉溶（会双影，见 §4 缺陷 1） |
| `key_zoom` | ≈1 … 6 | 仅 `draw`（半身键帧）用：默认 1 = 与全身脸同大（很小），当特写插镜时给 4~6 |

耗时 & 内存：`warm()` 后每张 1024 mip 以 uint8 缓存（色 4.2MB + alpha 1.4MB ≈ 5.6MB/张，13 张约 73MB）。

## 2. 权重场怎么算（`_weights()`）

全部在**单位空间**（y 向上、脚底=0、眼线=1）的一张 `248×262` 粗网格上算一次，之后每帧只算
「每根骨的仿射位移」在网格上取加权和 → 插值放大到落点包围盒 → **一次 `cv2.remap`** 把整张图揉掉。
关节处的过渡是**距离场 + 平顶软边界**，所以没有拼贴接缝。

### 2.1 骨架（父子链，`bone_affines()`）

```
root(髋) ─┬─ spine(脊柱) ─┬─ head(颈→头)
          │               ├─ sh_r → el_r → ha_r → sword      （右臂 = 画面左臂 = 持刀手）
          │               └─ sh_l → el_l → ha_l
          ├─ skirt(衣摆)
          └─ leg(腿，按高度渐变的竖向压缩 = 重心下沉)
```

* 关节点全部从 alpha/皮肤**实测**：脸/手用皮肤连通块，肩 `(±0.100, 0.890)`，肘 = 肩腕中点外推，
  腕 = 手块质心（实测 front：手在 `(±0.161, 0.561)`，与 tq_r/side_r 各自实测值一致到 ±0.02 —— 说明这套
  归一化坐标是对的）。
* 每根骨带一个 2×3 仿射（旋转/剪切/平移），父子相乘 → 抬手臂时头/躯干自然跟随，不用手写补偿。

### 2.2 每个权重的成员度

|l 场|怎么来|
|---|---|
|`head`|头心 `(0, 1.055)` 的平顶椭圆 `exp(-((dx/0.098)²+(dy/0.135)²)²)` **+ 0.9·thin·sstep(0.78,0.88,y)**（发丝 / 发髻 / 披发跟着头走，靠「离轮廓的细度」判别）|
|`spine`|按高度分层 `sstep(0.495,0.595)`×`sstep(1.00,0.93)`，再乘一个 `core` 系数把**外侧 |x| 让给手臂**|
|`skirt` / `leg`|髋以下按高度分出两段（衣摆 0.85 权重、腿 1.0），腿骨的位移在 `_disp()` 里按 `y/HIP` 渐变（脚底不动）|
|`sh_*` / `el_*`|到「肩→肘」「肘→腕」**胶囊的平顶距离场** `exp(-(d/r)⁴)`，`r=0.052/0.045`，再乘 `sstep(0.048,0.090,±x)` 外侧门——只在肢体自己那块地上占优|
|`ha_*`|腕点周围的平顶圆盘（`r=0.042`）|
|`sword`|「右手→刀尖」的窄带 `exp(-(d/0.024)⁴)` ∩ **细结构硬门槛** `sstep(0.30,0.55, thin)`，再加腕部 0.9 权重（刀柄跟手）|
|`root`|常数 0.05 兜底，保证归一化不除零|

`thin`（细结构）＝对 alpha 做距离变换，`thin = clip(1 − dt/(0.020·H))^1.5`：刀身和发丝很细、躯干/腰带很厚。
刀必须靠它挡住衣摆（否则转刀会在腰带上挖洞）。

归一化：`w_i / Σw_j`（逐像素）。**关键教训**：第一版用普通高斯（`exp(-(d/r)²)`），肢体权重只有 ~0.5，
抬手只抬一半、同时把胸口拉出一团淤积；改成 `pw=4` 平顶场后肢体权重 0.83+，才正常。

### 2.3 转头（`_angle_plan()` / `_all` 传 `squash=True`）

* 每张角度图都按**「眼线→脚底」归一化**（`_geom()` 实测：皮肤块顶 + 21%·脸框高 = 眼行；
  front 实测 H=1045px、头顶 1.116、腰 0.565、手 (±0.161,0.561)），所以同一单位空间里直接可换。
* 角度表（名字、文件、**实测头部偏转**、限定用途）：
  `front 0.0` / `tq_r 0.30`（生图只转了约 20°，且只给身体用）/ `tq_r_m 0.45`（= `view_tq_l` **镜像**，
  补右侧 40° 头）/ `side_r 1.0` / `tq_l −0.45` / `side_l −1.0`（= `side_r` 镜像）/ `back 1.7`。
* 选层规则：**只有当目标与两个角度都很近（|Δ|和 < 0.36）才做交叉溶**（smoothstep）；否则取最近的角度
  **+ 水平余弦挤压** `sx = cos(yaw_target)/cos(yaw_src)`（下限 0.70，绕脸心，脸的位置不动）。
  原因：把 20° 的脸和 90° 的脸各叠一半 = 糊成双影；挤压虽然保守，但不糊。
* 头部单独一层：先用**实测头 mask**（`headmask`，由 `head` 权重场 × 轮廓羽化再模糊两次得到，含头发、
  不含肩膀）把正面的旧头**擦掉**，再把新头叠上去（底边 0.855→0.948 溶进衣领）。
  这里如果改用矩形窗擦除会啃掉肩膀（第一版的坑）。

### 2.4 表情（`_expr_patch()`）

特写图只用来贴**脸**（眉上一点 → 下巴下一点，横向 0.84 脸宽），不换整颗头 —— 特写图的头发被画框切掉，
整头替换会在发际线留一圈残影。
定位只用两个几何量：脸宽 `facew`（皮肤块宽）和眼行（皮肤块顶 + 21%·脸框高），全身/特写用**同一套规则**，
所以自然对齐。落位后用**椭圆羽化** + **与原脸的均值差修正**（补丁与底图脸区平均色的差，夹 ±0.12）。
`expr='look'` 是 3/4 侧脸，要和 `head_turn≈0.4~0.6` 一起用，否则脸会对不上。

### 2.5 整姿势键帧（`key`）

`pose_raise / pose_slash` 按「脚底中点 + 自己的头顶比例」对齐到同一落点、`key_w` 交叉溶；
`pose_draw` 是半身（`bust`，用脸宽定尺度），按**眼线对齐**，配 `key_zoom` 放大成特写。
键帧权重越高，骨架形变越弱（`dscale = 1 − 0.85·key_w`），避免「键帧姿势 + 骨架再扭一遍」的双重形变。

### 2.6 洞补（`_fill_holes()`）

二维贴图蒙皮的固有缺陷：手臂/刀底下的像素在原图里是不存在的。变形后如果轮廓内出现空洞
（`preA>0.6 且 A<0.45`），用 `cv2.inpaint(TELEA)` 补色 + 恢复 alpha，相当于「补画被手臂挡住的躯干」。
`arm_r` 抬到 60° 以上时这个洞补是主要防线。

## 3. 耗时（`out/rig_test/timings.json`）

条件：8 核机器、**单进程、`OMP/OPENBLAS/MKL=1`**、`h=680`、`work_w=1024`，每姿势 4 次取中位数（同一轮的 `timings.json` 就是这张表）。
（测的时候机器 load average ≈ 8.8、还有别的代理在跑；空载时同样的代码 idle 能到 43ms，
所以下表是**偏悲观**的数字。多跑几次取最小值更接近真实值。）

| 姿势 | 中位数 | 最小 | 备注 |
|---|---|---|---|
| idle | 62 ms | 59 | 权重场=0 → 恒等映射 |
| head_turn −0.6 | 78 | 74 | 头部两层（擦旧头 + 贴新头） |
| head_turn 0 | 71 | 65 | |
| head_turn +0.6 | 86 | 81 | 镜像 40° 头 + 余弦挤压 |
| arm_r 45° | 87 | 80 | |
| arm_r 90° | 78 | 77 | |
| lean 0.2 | 82 | 80 | |
| slash 中段 key_w .5 + mblur7 | 107 | 105 | 两层 + 方向模糊 |
| slash 落刀 key_w 1 | 104 | 89 | |
| expr angry | 62 | 52 | |
| expr smirk | 57 | 51 | |
| expr look（+turn 0.5） | 61 | 59 | |
| raise 举刀 key_w 1 | 81 | 76 | |
| （对比）现有单张立绘 sprite | **114** | — | `SpriteLayer` 同高度同调色 |

**结论：单帧 52~107 ms，比要求的 < 250 ms 有 2~4 倍余量；顺手比现有单张 sprite（114ms）还快。**
`init` 0.26s，`warm()` 2.4s（预解码 13 张），首帧抖动靠它消掉。
`look='sil'/'ink'/'paper'/'neg'/'shadow'` 各加 ~30ms（在同一个包围盒里跑 `sprite._look`）。

## 4. 已知缺陷（会穿帮的地方 + 为什么）

1. **键帧中间值（`key_w` 0.2~0.8）双影** —— 两个不同姿势的整图交叉溶，必然重影。
   这是「整姿势键帧」这条路线的固有代价：**只在 2~3 帧内快速拉过去 + 配 `mblur`**，
   `slash 中段`那张样张就是 `key_w=0.5 + mblur=7` 才有动势。要单帧干净的中间姿势，得再补一张
   「横刀中段」生图当第三个键帧（`pose_raise → 新图 → pose_slash`）。
2. **`body_turn` 默认 0，不要随便开** —— 两张不同身体姿势的正身交叉溶同样是双影（turn 样张里
   之前那版明显）。所以 `head_turn` 只换头不换身体。身体真转身需要**独立的转身关键帧图**
   （同一姿势的 45°/90° 身体），否则只能靠 `twist` 的二维剪切。
3. **`arm_r` > 60° 大袖会淤积/折叠**，`elbow_r` 越大越明显：二维蒙皮没有「袖子底下的躯干」，
   腋下那块会被拉成一道褶；同时**刀镡 + 红穗**绕腕转起来会变成一团深色椭圆（其实是真的刀镡，只是
   平时被刀身挡着）。**抬手 ≥60° 请直接用 `key='raise'`**，`arm_r` 只当 0~45° 的微调和小幅摆动。
4. **`head_turn` 观感比参数保守**：右侧只有 tq_r（≈20°）和 side_r（90°）两档，中间靠挤压补，
   `|head_turn|` 在 0.3~0.7 看起来会「比标称少转一点」。**要真正的 45° 头，需要补一张
   `hero_view_tq_r45`（右侧 45°）生图** —— 现在右侧 40° 是 `view_tq_l` 的镜像顶着的，
   镜像会左右反（发髻/刘海偏的方向跟着反，脸本身没问题）。
5. **镜像只给头用**：`side_l`、`tq_r_m` 都是镜像图，身体镜像会「刀换手」，所以它们标了 `head` 专用。
6. **`expr` 只换脸、不换头**：`angry/smirk` 效果好；`look`（3/4 侧脸）必须配 `head_turn≈0.5`，
   否则脸被压扁/错位。表情补丁也不会跟着 `head_turn` 走 —— `head_turn` 大时补丁会「贴歪」。
   另外补丁顶部只取到眉毛以上一点：再往上会把特写的刘海带进来，在额头上留几道黑线（试过，很难看）。
7. **刀没有前后遮挡关系**：刀始终按正面图那样画在身体前（或后）一层，抬臂后刀可能该在身后却仍在身前。
   要修得给刀单独一层 + 每帧按 y 排序，属于下一步。
8. **`lean` 是二维近似**：正面视角的前后倾只能靠画面内倾斜 + 头/肩反补，不是真正的透视缩短。
   真要前后倾，得用 `side_r` 的正身（又是一张关键帧）。
9. **头发**：转头时整块头发（含披发）会跟着头转，`headmask` 擦除后由新角度的头发补上；长发披肩那块
   在两个角度之间会有轻微「厚薄变化」，静态单帧还好，连续转头能看出头发体积在变。
10. **`work_w` 上限 1280**：解码 mip 更大不会更清楚（最终落点只有 `h` 像素），只会更慢更占内存。
11. 蒙皮会让**皮革护腕、腰带纹样被轻微拉伸**（LBS 挤压），幅度大的关节处（腋下、肘）最明显。
12. **`key='draw'`（半身键帧）是「特写插镜」而不是全身姿势**：`key_zoom` 放大到铺满画面时，
    会看到源图自己的画框边（一条硬直边，见 §2.5）；构图时把那条边推到画面外即可。

## 5. 怎么用（接到现有管线）

```python
import os
os.environ['SPRITE_MODE'] = '1'
from units.rig_sprite import PoseRig

RIG = PoseRig(base='assets/gen/char', work_w=1024).warm()   # 模块级单例，载入时一次

# 每个镜头里：
fr, a = RIG.draw(fr, t, dict(head_turn=-0.4, arm_r=20, knee=0.1, expr='angry'),
                 dst=(cam.x, cam.y), h=frame_h, grade=GRADE, rim=RIM, look=None)
```

* 多个精灵同镜（群像）时，权重场/贴图是模块级缓存共享的，只有 `draw` 的计算是每帧的。
* 单进程、线程数限死（`OMP_NUM_THREADS=1` 等），同时最多 2 个渲染进程。
* 想回滚：`units/rig_sprite.py` + `tools/rig_pose_test.py` 是纯新增文件，直接删掉即回到 `sprite.py` 老路径。

## 6. 下一步建议（优先级）

1. 补一张「横刀中段」全身图 → `key` 三键帧，彻底解决劈砍中间帧双影。
2. 补右侧 45° 全身（`hero_view_tq_r45`）→ 转头对称、不用镜像。
3. 刀单独成层 + 每帧深度排序（`arm_r` 大幅抬起时刀会错层）。
4. 正身 45°/90° 关键帧 → 真正的身体转身（`body_turn` 才敢开）。
